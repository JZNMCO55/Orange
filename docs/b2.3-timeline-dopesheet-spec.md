> **headless 数据原语**（AnimationClip/Track/Keyframe + SampleTrack + CRUD）接到底部
> Animation 面板的 timeline/dopesheet UI。**精确在数据↔交互的映射 + 接入点 + 命令栈

## 已就绪的数据原语（headless，直接调用，无需新引擎代码）

| UI 交互 | 调用的数据原语（`AnimationClip.h`） |
|---|---|
| playhead scrub（拖时间线游标） | `ClipAnimator::Seek(t)`（内部 WrapClipTime + ApplyPose，实体实时跟随）/ 或纯预览用 `SampleTrack` |
| 显示某轨道某时刻值 | `SampleTrack(track, t)` |
| 在 playhead 打键（K） | `UpsertKeyframe(clip, targetName, valueType, key)`（按需建轨 + 同时间覆盖） |
| dopesheet 水平拖 key 改时间 | `MoveKeyframeTime(track, index, newTime)`（重排维持升序） |
| 点选 key（点击命中） | `FindKeyframeIndexNear(track, t, tol)` |
| 删 key | `RemoveKeyframe(track, index)` |
| 加/删轨道 | `UpsertTrack` / `RemoveTrack(clip, targetName)` |
| 时间线总长 | `ComputeClipDuration(clip)`（或 clip.duration） |
| loop 区间显示 | `clip.loop` + `WrapClipTime` |

**关键：UI 不需要新的引擎采样/编辑逻辑，全是已落地原语的可视化壳。** 这是 B2.1/B2.1b
"先做数据层"的回报。

## 设计点 1：timeline 编辑哪个 clip？（数据归属）

面板编辑「当前选中实体的 AnimatorComponent 里的 ClipAnimator 的 clip」。但：
- **`ClipAnimator::Clip()` 当前是 const**（只读）。timeline 编辑要改 clip → 两条路：
  - (a) **可变访问**：给 ClipAnimator 加 `AnimationClip& MutableClip()` + 改后调内部
    `RecomputeDuration`/重置 elapsed。简单，但绕过命令栈难做 Undo。
  - (b) **copy-modify-SetClip**（**推荐**，与编辑器命令栈一致）：编辑命令持「旧 clip 快照
    + 新 clip」，do/undo 都 `SetClip`。与现有 Inspector 字段命令同心智（CaptureComponentState
    → 改 → 命令栈）。代价：每次编辑拷整个 clip（clip 通常小，可接受；大 clip 再优化为
    per-key 命令）。
- **若 clip 来自 .anim 资产**（`SourceAssetPath` 非空，b2.6 改点 1）：timeline 编辑应
  **写回 .anim 文件**（`SaveAnimationClip`），否则 in-memory 改动与资产文件发散（save scene
  时只存 clipSource 引用 → 改动丢失）。UI 需「保存到 .anim」动作 + dirty 标记。内联 clip
  （无 source）则随 scene 存（clipJson）。

## 设计点 2：编辑期播放/预览 tick（与 b2.6 改点 3 共享）

Edit 模式不跑 `TickAnimators`。timeline 的播放/scrub 预览要让被编辑实体动：
- scrub：直接 `ClipAnimator::Seek(t)`（写实体 Transform，下一帧渲染可见）。
- 播放预览（▶ 按钮）：面板自己每帧 `anim->Tick(dt)` **仅对当前编辑的 animator**（不是
  PlayState::Play 的全量 tick）——**新机制，dogfood 重点**：与 PlayState::Play 不打架、
  停止预览后实体归位到 scrub 位置（或 Stop 到 t0）。

## 设计点 3：命令栈集成

每个 key 编辑（打/拖/删）走命令栈（Undo/Redo）。复用现有 `CaptureComponentState` 路径
需让它认 AnimatorComponent 的 ClipAnimator clip（参 AssetRefArray 的 capture 分支，
`RegisterBuiltinSchemas.cpp` SubMeshMaterials 段）。MVP 可先用「整 clip 快照」命令
（设计点 1(b)），后续优化为 per-key 命令 + merge（连续拖同一 key 合并，参
MoveEntityCommand merge）。

## 实施顺序（建议）

1. **只读 timeline**（无编辑）：画轨道行 + key 点 + playhead；scrub 调 Seek 预览。验证
   数据↔UI 映射正确（headless 数据已测，这步验「画得对」）。
2. **打键 / 删键**（K / Del）：UpsertKeyframe / RemoveKeyframe + 命令栈。
3. **拖 key 改时间**：MoveKeyframeTime + 命令栈 + merge。
4. **播放预览**（▶）：编辑期单 animator tick（dogfood 重点）。
5. **轨道增删 + .anim 写回**（资产化 clip）。
6. **曲线编辑器**（B2.4）：单独 milestone，Bezier handle 拖动改 `inTangent/outTangent.y`
   缓动；曲线视图与 SampleTrack 的 Hermite 插值一致。

## dogfood 计划（落地后追加 dogfood-checklist）

- 选中带 ClipAnimator 的实体 → Animation 面板显示其 clip 轨道 + key。
- 拖 playhead → 实体实时跟随（scrub 预览）。
- K 打键 / 拖 key 改时间 / Del 删键 → Undo/Redo 一次一步回退。
- ▶ 播放预览 → 实体动；停止归位；与 PlayState::Play 不冲突（编辑期 tick 新机制重点）。
- 资产化 clip 编辑 → 保存到 .anim → 重开仍在。
