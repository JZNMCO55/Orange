# Orange引擎开发文档

## Memory系统技术文档

### 概述
Orange引擎的Memory系统是一个自定义内存管理框架，提供内存分配跟踪、统计分析和调试功能。系统包含自定义分配器、全局操作符重载、线程安全保护等企业级特性。

### Memory系统架构

#### 核心数据结构

**1. AllocationStats（分配统计）**
```cpp
struct AllocationStats
{
    size_t TotalAllocated = 0;  // 总分配字节数
    size_t TotalFreed = 0;      // 总释放字节数
};
```

**2. Allocation（分配记录）**
```cpp
struct Allocation
{
    void* Memory = 0;           // 分配的内存地址
    size_t Size = 0;            // 分配的内存大小（字节）
    const char* Category = 0;   // 分配类别标识（文件名或描述）
};
```

**3. Mallocator（自定义分配器模板）**
```cpp
template <class T>
struct Mallocator
{
    typedef T value_type;
    T* allocate(std::size_t n);
    void deallocate(T* p, std::size_t n) noexcept;
};
```

**4. AllocatorData（分配器数据存储）**
```cpp
struct AllocatorData
{
    std::map<const void*, Allocation> m_AllocationMap;  // 内存映射表
    AllocationStatsMap m_AllocationStatsMap;            // 统计映射表
    std::mutex m_Mutex, m_StatsMutex;                   // 线程同步锁
};
```

#### Allocator类接口

**初始化管理**
```cpp
// 初始化内存分配器
static void Init();

// 原始内存分配（不跟踪）
static void* AllocateRaw(size_t size);
```

**内存分配接口**
```cpp
// 基础分配（带跟踪）
static void* Allocate(size_t size);

// 带描述的分配（用于分类统计）
static void* Allocate(size_t size, const char* desc);

// 带文件行号的分配（用于调试）
static void* Allocate(size_t size, const char* file, int line);

// 内存释放
static void Free(void* memory);
```

**统计信息**
```cpp
// 获取分配统计信息
static const AllocationStatsMap& GetAllocationStats();

// 获取全局统计
const AllocationStats& Memory::GetAllocationStats();
```

### 全局操作符重载（Windows平台）

Memory系统在Windows平台下提供完整的全局new/delete操作符重载：

```cpp
// 基础操作符
void* operator new(size_t size);
void* operator new[](size_t size);
void operator delete(void* memory);
void operator delete[](void* memory);

// 带描述的操作符
void* operator new(size_t size, const char* desc);
void* operator new[](size_t size, const char* desc);
void operator delete(void* memory, const char* desc);
void operator delete[](void* memory, const char* desc);

// 带文件行号的操作符
void* operator new(size_t size, const char* file, int line);
void* operator new[](size_t size, const char* file, int line);
void operator delete(void* memory, const char* file, int line);
void operator delete[](void* memory, const char* file, int line);
```

### 线程安全机制

Memory系统采用互斥锁确保线程安全：

```cpp
// C++14兼容的线程锁
std::lock_guard<std::mutex> lock(s_Data->m_Mutex);

// 临界区保护
{
    std::lock_guard<std::mutex> lock(s_Data->m_Mutex);
    // 安全的内存映射操作
    Allocation& alloc = s_Data->m_AllocationMap[memory];
    alloc.Memory = memory;
    alloc.Size = size;
    alloc.Category = desc;
}
```

系统提供内存泄漏检测功能：

```cpp

```

### 错误修复记录

#### C++14兼容性修复
原代码使用了C++17的`std::scoped_lock`，修复为C++14兼容的`std::lock_guard`：

```cpp
// 修复前（C++17）
std::scoped_lock<std::mutex> lock(s_Data->m_Mutex);

// 修复后（C++14兼容）
std::lock_guard<std::mutex> lock(s_Data->m_Mutex);
```

#### Tracy集成修复
添加条件编译保护，避免Tracy头文件缺失导致的编译错误：

```cpp
#if ORG_ENABLE_PROFILING
    // Tracy只在启用性能分析时使用
    TracyAlloc(memory, size);
#endif
```

#### Logger集成修复
修正Logger宏调用格式，确保参数正确传递：

```cpp
// 修复Logger宏调用
ORG_CORE_WARN_TAG("Memory", "Memory block not present in alloc map");
```

### 性能特性

1. **零开销抽象**：在非跟踪模式下性能等同于标准malloc/free
2. **最小锁粒度**：只在关键数据结构操作时加锁
3. **内存对齐**：保持与系统分配器相同的内存对齐
4. **分类统计**：支持按文件或描述进行内存使用分析

### 平台支持

- **Windows**: 完整支持，包括全局操作符重载
- **其他平台**: 基础功能支持，不包含操作符重载

## Buffer系统技术文档

### 概述

Orange引擎的Buffer系统提供通用的内存缓冲区管理功能，支持多种数据类型的存储和操作。系统包含基础缓冲区类和自动内存管理的安全缓冲区类。

### 核心类设计

#### Buffer类

基础缓冲区类，提供内存缓冲区的分配、管理和访问功能：

```cpp
struct Buffer
{
    void* Data = nullptr;   // 缓冲区数据指针
    uint64_t Size = 0;      // 缓冲区大小（字节）
};
```

**构造方式**
```cpp
// 默认构造（空缓冲区）
Buffer buffer;

// 从指针和大小构造
Buffer buffer(data, size);

// 从std::array构造
std::array<float, 100> arr;
Buffer buffer(arr);

// 从std::vector构造
std::vector<int> vec;
Buffer buffer(vec);
```

**内存管理**
```cpp
// 分配内存
buffer.Allocate(1024);

// 释放内存
buffer.Release();

// 清零内存
buffer.ZeroInitialize();
```

**数据访问**
```cpp
// 类型化读取
float& value = buffer.Read<float>(offset);
const int& data = buffer.Read<int>(offset);

// 字节数组读取
byte* bytes = buffer.ReadBytes(size, offset);

// 数据写入
buffer.Write(data, size, offset);

// 数组访问
byte b = buffer[index];
buffer[index] = value;

// 类型转换
float* floatPtr = buffer.As<float>();
```

**实用功能**
```cpp
// 复制缓冲区
Buffer copy = Buffer::Copy(original);
Buffer copy2 = Buffer::Copy(data, size);

// 检查有效性
if (buffer) {
    // 缓冲区包含有效数据
}

// 获取大小
uint64_t size = buffer.GetSize();
```

#### BufferSafe类

继承自Buffer，提供RAII语义的自动内存管理：

```cpp
struct BufferSafe : public Buffer
{
    ~BufferSafe() { Release(); }  // 析构时自动释放内存
};
```

**使用示例**
```cpp
// 自动内存管理
{
    BufferSafe buffer;
    buffer.Allocate(1024);
    // 作用域结束时自动释放内存
}

// 复制创建
BufferSafe safeCopy = BufferSafe::Copy(data, size);
```

### 使用场景

#### 1. 文件数据处理
```cpp
// 读取文件到缓冲区
BufferSafe fileBuffer;
fileBuffer.Allocate(fileSize);
file.read(fileBuffer.As<char>(), fileSize);

// 解析文件头
FileHeader& header = fileBuffer.Read<FileHeader>();
```

#### 2. 网络数据包处理
```cpp
// 构造数据包
Buffer packet;
packet.Allocate(sizeof(PacketHeader) + dataSize);
packet.Write(&header, sizeof(PacketHeader));
packet.Write(data, dataSize, sizeof(PacketHeader));
```

#### 3. 渲染数据管理
```cpp
// 顶点数据缓冲区
std::vector<Vertex> vertices;
Buffer vertexBuffer(vertices);

// 上传到GPU
renderer.UploadVertexData(vertexBuffer.Data, vertexBuffer.Size);
```

#### 4. 序列化支持
```cpp
// 序列化对象
Buffer serializeBuffer;
serializeBuffer.Allocate(object.GetSerializedSize());
object.Serialize(serializeBuffer);

// 反序列化
Object newObject;
newObject.Deserialize(serializeBuffer);
```

### 设计特点

1. **简单高效**: 基于原始指针，避免不必要的抽象开销
2. **类型安全**: 模板化的读写接口，编译时类型检查
3. **内存管理**: 支持手动和自动两种内存管理方式
4. **容器兼容**: 直接支持STL容器的数据访问
5. **边界检查**: 在Debug模式下提供断言保护

### 注意事项

1. **内存安全**: Buffer类不自动管理内存，需要手动调用Release()
2. **边界检查**: 读写操作不进行运行时边界检查，需要调用者保证安全
3. **数据对齐**: 不处理数据对齐问题，需要调用者注意结构体对齐
4. **线程安全**: 不提供线程安全保证，多线程使用需要外部同步

## Profiler系统技术文档

### 概述

Orange引擎的Profiler系统提供性能分析和调试支持，集成Tracy性能分析器，支持函数级别和作用域级别的性能跟踪。

### 系统配置

性能分析功能通过条件编译控制：

```cpp
#define ORG_ENABLE_PROFILING !ORG_DIST  // 非发布版本启用
```

### 核心宏定义

#### 帧标记
```cpp
// 标记帧边界（通常在主循环中调用）
ORG_PROFILE_MARK_FRAME
```

#### 函数和作用域分析
```cpp
// 函数级别分析（在函数开头使用）
ORG_PROFILE_FUNC()
ORG_PROFILE_FUNC("CustomName")

// 作用域分析
ORG_PROFILE_SCOPE()
ORG_PROFILE_SCOPE("ScopeName")

// 动态命名作用域
ORG_PROFILE_SCOPE_DYNAMIC(variableName)
```

#### 线程标记
```cpp
// 设置线程名称
ORG_PROFILE_THREAD("RenderThread")
ORG_PROFILE_THREAD("WorkerThread")
```

### 使用示例

#### 1. 基础函数分析
```cpp
void RenderFrame()
{
    ORG_PROFILE_FUNC();  // 分析整个函数
    
    // 渲染逻辑
    PrepareRenderData();
    ExecuteRenderCommands();
    PresentFrame();
}
```

#### 2. 作用域分析
```cpp
void UpdateGame(float deltaTime)
{
    ORG_PROFILE_FUNC();
    
    {
        ORG_PROFILE_SCOPE("Physics");
        physicsWorld.Step(deltaTime);
    }
    
    {
        ORG_PROFILE_SCOPE("AI");
        aiSystem.Update(deltaTime);
    }
    
    {
        ORG_PROFILE_SCOPE("Animation");
        animationSystem.Update(deltaTime);
    }
}
```

#### 3. 动态命名分析
```cpp
void ProcessAssets()
{
    for (const auto& asset : assets)
    {
        std::string scopeName = "Process_" + asset.GetName();
        ORG_PROFILE_SCOPE_DYNAMIC(scopeName.c_str());
        
        asset.Process();
    }
}
```

#### 4. 线程分析
```cpp
void RenderThreadMain()
{
    ORG_PROFILE_THREAD("RenderThread");
    
    while (running)
    {
        ORG_PROFILE_MARK_FRAME;
        
        {
            ORG_PROFILE_SCOPE("RenderLoop");
            ProcessRenderCommands();
        }
    }
}
```

#### 5. 主循环集成
```cpp
int main()
{
    ORG_PROFILE_THREAD("MainThread");
    
    while (gameRunning)
    {
        ORG_PROFILE_MARK_FRAME;
        
        {
            ORG_PROFILE_SCOPE("GameLoop");
            
            HandleInput();
            UpdateGame(deltaTime);
            RenderFrame();
        }
    }
    
    return 0;
}
```

### Tracy集成

当启用性能分析时，系统自动集成Tracy分析器：

```cpp
#if ORG_ENABLE_PROFILING 
    #include <tracy/Tracy.hpp>
    
    #define ORG_PROFILE_FUNC(...) ZoneScoped##__VA_OPT__(N(__VA_ARGS__))
    #define ORG_PROFILE_SCOPE_DYNAMIC(NAME) ZoneScoped; ZoneName(NAME, strlen(NAME))
#endif
```

### 性能影响

1. **Debug模式**: 完整的性能分析功能，有一定性能开销
2. **Release模式**: 保留性能分析，优化后开销较小
3. **Distribution模式**: 完全禁用，零性能开销

### 最佳实践

#### 1. 分析粒度
```cpp
// 好的做法：分析关键函数和热点代码
void CriticalFunction()
{
    ORG_PROFILE_FUNC();
    // 重要逻辑
}

// 避免：过度细粒度分析
void TrivialFunction()
{
    // ORG_PROFILE_FUNC();  // 不必要的开销
    return x + y;
}
```

#### 2. 命名规范
```cpp
// 使用有意义的名称
ORG_PROFILE_SCOPE("PhysicsSimulation");
ORG_PROFILE_SCOPE("TextureLoading");
ORG_PROFILE_SCOPE("ShaderCompilation");

// 避免无意义的名称
// ORG_PROFILE_SCOPE("Loop1");
// ORG_PROFILE_SCOPE("Temp");
```

#### 3. 线程标识
```cpp
// 为每个重要线程设置名称
void WorkerThread()
{
    ORG_PROFILE_THREAD("Worker");
    // 工作逻辑
}

void AudioThread()
{
    ORG_PROFILE_THREAD("Audio");
    // 音频处理
}
```

### 条件编译优化

在不同构建模式下，宏会自动优化：

```cpp
#if ORG_ENABLE_PROFILING
    // 启用完整分析功能
    #define ORG_PROFILE_FUNC(...) ZoneScoped##__VA_OPT__(N(__VA_ARGS__))
#else
    // 禁用时编译为空宏，零开销
    #define ORG_PROFILE_FUNC(...)
#endif
```

## Logger系统技术文档

### 概述

Orange引擎的Logger系统是一个高性能、功能丰富的日志记录框架，参考Hazel引擎设计理念，提供企业级的日志管理功能。系统支持多级别日志、标签化分类、条件编译优化等特性。

### Logger系统架构

#### 核心组件

**1. Logger类**
- 位置：`Src/OrangeEngine/Layer1/Core/Base/Logger.h/cpp`
- 功能：提供静态接口的日志管理器
- 特性：双日志器系统（Core/Client分离）

**2. 日志级别系统**
```cpp
enum class Level : uint8_t
{
    Trace = 0,    // 最详细的调试信息
    Debug,        // 调试过程中的详细信息
    Info,         // 一般性操作信息
    Warn,         // 潜在问题但不影响运行
    Error,        // 错误情况但程序可继续
    Critical      // 严重错误可能导致程序终止
};
```

**3. 日志器类型**
```cpp
enum class Type : uint8_t
{
    Core = 0,     // 引擎核心日志
    Client = 1    // 客户端应用日志
};
```

**4. 标签化系统**
```cpp
struct TagDetails
{
    bool mEnabled = true;                    // 标签是否启用
    Level mLevelFilter = Level::Trace;       // 最低日志级别过滤
};
```

### 条件编译优化

系统根据构建配置自动优化性能：

**Debug模式（ORG_DEBUG）**
- 启用所有日志级别
- 启用所有断言和验证
- 最详细的调试信息

**Release模式（ORG_RELEASE）**
- 禁用Trace和Debug级别日志
- 禁用断言，保留验证
- 平衡性能和信息量

**Distribution模式（ORG_DIST）**
- 只保留Critical级别日志
- 禁用断言和验证
- 最佳运行时性能

### 实现特点

#### 1. 简单可靠的实现
- 避免复杂的第三方依赖
- 使用基础的std::ofstream进行文件输出
- 保证在各种环境下的编译稳定性

#### 2. 线程安全
- 内部使用互斥锁保护共享数据
- 支持多线程环境下的并发日志记录
- 与内存管理系统协同工作

#### 3. 性能优化
- 宏展开避免函数调用开销
- 条件编译消除不需要的代码
- 最小化字符串处理开销

#### 4. 平台集成
- Windows平台支持MessageBox断言显示
- 为tracy性能分析器预留接口
- 支持跨平台编译

### 使用最佳实践

#### 1. 标签选择
```cpp
// 好的做法：使用有意义的标签
ORG_CORE_INFO_TAG("Renderer", "Shader compiled successfully");
ORG_INFO_TAG("GameLogic", "Player level up to " + std::to_string(level));

// 避免：过于频繁的日志
// ORG_CORE_TRACE_TAG("Timer", "Frame time: " + deltaTime); // 每帧都输出
```

#### 2. 级别选择
```cpp
// Critical: 导致程序无法继续的严重错误
ORG_CORE_CRITICAL_TAG("Core", "Failed to initialize graphics device");

// Error: 功能性错误但程序可以继续
ORG_CORE_ERROR_TAG("Asset", "Failed to load texture: " + filename);

// Warn: 潜在问题或不推荐的使用方式
ORG_CORE_WARN_TAG("Memory", "Memory usage exceeds 80%");

// Info: 重要的状态变化和操作结果
ORG_CORE_INFO_TAG("Scene", "Scene loaded: " + sceneName);

// Debug: 调试时需要的详细信息
ORG_CORE_DEBUG_TAG("Physics", "Collision detected between objects");

// Trace: 最详细的执行流程跟踪
ORG_CORE_TRACE_TAG("Core", "Entering main loop iteration");
```

#### 3. 初始化序列
```cpp
int main()
{
    // 1. 首先初始化日志系统
    Orange::Logger::Init();
    
    // 2. 配置自定义标签（可选）
    auto& tags = Orange::Logger::EnabledTags();
    tags["GameLogic"] = {true, Orange::Logger::Level::Info};
    
    // 3. 记录启动信息
    ORG_CORE_INFO_TAG("Core", "Orange Engine starting up");
    
    // ... 应用程序逻辑 ...
    
    // 4. 程序退出前关闭日志系统
    ORG_CORE_INFO_TAG("Core", "Orange Engine shutting down");
    Orange::Logger::Shutdown();
    
    return 0;
}
```

### 与内存系统集成

Logger系统与Orange内存管理系统深度集成，支持内存分配的日志记录：

```cpp
// 内存分配失败时的自动日志记录
void* ptr = Orange::Allocator::Allocate(1024, "RenderBuffer");
if (!ptr) {
    ORG_CORE_ERROR_TAG("Memory", "Failed to allocate render buffer");
}

// 内存泄漏检测的日志输出

```

### 文件输出

日志文件自动创建在`logs/`目录下：
- `ORANGE_CORE.log`: 核心系统日志
- `ORANGE_CLIENT.log`: 客户端应用日志

文件格式：`[TYPE] LEVEL: MESSAGE`
例如：`[CORE] INFO: Engine initialized successfully`

### 故障排除

#### 常见问题

1. **日志不显示**
   - 检查Logger::Init()是否被调用
   - 检查标签是否启用
   - 检查日志级别是否足够

2. **编译错误**
   - 确保包含正确的头文件
   - 检查ORG_DEBUG等宏定义
   - 验证CMake配置

3. **性能问题**
   - 在Release/Distribution模式下检查
   - 减少高频日志输出
   - 考虑提高日志级别过滤
