# B2.5 状态机图编辑器 spec —— 节点图 UI（数据底座已就绪）

> 给编辑器 session 的蓝图（pure-doc）。**B2.5 是 B2 四件套里数据最完整的**：
> AnimationStateMachine 数据 + `.anim_fsm` 序列化 + 命令栈 + 列表式 inspector **全已存在**，
> **只缺节点图可视化 UI**（状态=可拖节点 / transition=边）。优先级低于 timeline（B2.3）
> 与 Inspector clip（B2.6）——用户重点是「动画时序编辑」，FSM 是次位。ImGui 节点绘制
> 细节留实现期 live 迭代，本 spec 给数据↔图映射 + 接入点 + 唯一真缺口（节点坐标存储）。

## 已就绪（无需新引擎代码）

- **数据**：`AnimationStateMachine`（`include/orange/engine/animation/AnimationStateMachine.h`）
  —— `AddState(name, onEnter, onExit)` / `AddTransition(from, to, ConditionExpr)` /
  `RegisterParameter(name, type)` / `SetInitialState`；`ConditionExpr{param, op, threshold}`
  数据驱动（ADR-005）。
- **序列化**：`.anim_fsm`（`tools/OrangeEditor/AnimFsmFileIO.h`）。
- **命令栈**：`tools/OrangeEditor/command/AnimFsmCommands.h`（AddState 等已接 Undo/Redo）。
- **列表式 inspector**：`AnimFsmAssetInspectorPlugin`（`CanHandle` `.anim_fsm`；已有
  `kAddStatePopupId` / **`kNodePopupId`**〔节点 context popup id 已埋〕）。

## 数据 ↔ 节点图映射

| 图元素 | 数据 |
|---|---|
| 节点（state） | `AnimationStateMachine` 的 state（name + onEnter/onExit）；initial state 高亮 |
| 边（transition） | `AddTransition(from, to, ...)`；边上 label = `ConditionExpr{param op threshold}` |
| 拖出一条边建 transition | `AnimFsmCommands` 的 AddTransition 命令 |
| 右键节点删/改 | 现有 node context popup（`kNodePopupId`）扩菜单 |
| 空白右键建 state | 现有 `kAddStatePopupId`，建在点击坐标 |
| 参数面板（侧栏） | `RegisterParameter` 列表（已有列表式编辑可复用） |

**结论同 B2.3：UI 是已落地数据/命令的可视化壳。**

## 唯一真缺口：节点坐标存储

state 当前**无编辑器坐标**（数据只有 name + 回调）。节点图要持久化每个 state 的 (x, y)。两条路：
- (a) **`.anim_fsm` schema 加 editorPos**（per-state {x,y}，minor bump；runtime 忽略该字段）——
  单文件自包含，**推荐**。沿用"schema 出厂冻结、扩字段走 minor"纪律。
- (b) sidecar `.anim_fsm.layout`——不污染 runtime schema，但多一个文件。
- 新建 state 落在点击坐标；自动布局（首次打开无坐标的旧 .anim_fsm）用简单分层/网格摆放。

## 接入点

- 复用 `AnimFsmAssetInspectorPlugin`（已 CanHandle `.anim_fsm`）：把当前列表视图升级/切换为
  节点图视图（或并存：列表 + 图 tab）。
- 或挂到底部 Animation 面板的「状态机」子模式（与 B2.3 timeline 子模式并列，
  `DrawAnimationPanel` EditorRenderLayer.cpp:2966 已 dock）。
- 节点绘制：ImGui `ImDrawList`（贝塞尔边 + 矩形节点 + hit-test）自绘，或评估 vendor
  `imnodes` / ImGui-node-editor（许可证 + 体量按 DCC import vendor 纪律核查）。

## 实施顺序

1. **只读图**：画节点（state）+ 边（transition）+ initial 高亮，坐标用自动布局。验证数据↔图映射。
2. **节点坐标存储**（缺口 (a)）：.anim_fsm schema 加 editorPos + 拖动落盘 + 命令栈。
3. **建/删 state**（空白右键 / 节点右键，复用现有 popup id + AnimFsmCommands）。
4. **拖边建 transition** + 边上 ConditionExpr 编辑（复用现有 condition 列表编辑）。
5. **运行高亮**（Play 模式当前 active state 节点高亮）——runtime 已就绪：
   `AnimationStateMachine::CurrentState()`（`AnimationStateMachine.h:188`，返回当前活跃状态名，
   未设时空 string_view）直接用，无引擎缺口。

## dogfood（落地后追加 checklist）

- 打开 `.anim_fsm` → 节点图显示 states + transitions，initial 高亮。
- 拖节点 → 位置存盘，重开保持。
- 右键建 state / 拖边建 transition / 编辑 condition → Undo/Redo。
- Play 模式 active state 高亮随参数变化跳转（需 runtime current-state）。
